# テストが確かめていること、確かめていないこと

## 生成文書の使いやすさ

```
node test/usability-fixtures.mjs [--dump <新規フォルダ>]
```

合成の案件で、次の 8 場面を 4 モードそれぞれについて確かめます。`--dump` を付けると、読み比べ用の生成物を出力します。

| 場面 | 確かめること |
| --- | --- |
| 未知の技術構成・空の新規案件 | 未定を残し、架空の手順を出さず、確認が 1 つの課題にまとまる |
| 実在する検証方法 | 候補と登録済みの検証レシピが区別され、登録して OK を記録した完了は診断を通る |
| 0 件成功・失敗・環境不能 | その結果のまま完了にすると診断が検出する |
| 多数のテスト成功、主要な経路は未検証 | 単体テストの成功だけの課題を完了にすると、その課題だけ検出する |
| 成果物への実験コードの混入 | 混入で NG の課題を完了にすると検出する |
| 編集と進捗がある状態での更新・別フォルダ生成 | 進捗が残り、確認後の変更で古い承認を拒否し、古い担当名が残らない |
| 参照の欠落と矛盾 | 欠落、役割の矛盾、不在の担当待ちを検出し、診断は復元しない |
| 次のセッションでの再開 | 再開メモの欄と、入口の再開時の導線がある |

これは構造・整合・保存・判定の検査です。「文書にそう書いてあること」だけを見ている項目も含みます。

## 確かめていないこと

- 標準・しっかりの段階の文書で、実際に案件を回した結果。実用性の評価ケース (上の 8 場面) は、最小の段階・以前の配置 (ルート) で実行している。新しい配置は `layout.test.mjs` で確かめている。
- 実際の AI のセッションが、文書どおりに読み、進めるか。
- Codexの既存ルール優先コピー以外の実セッション。1案件の全体コピーは内容一致・元案件の不変・退避を確認済み。Claude Codeと他モードの実際の対話は未確認。
- macOS / Linux での動作。symlink (junction 以外) を追わない経路。
- `update --online` の実際のネットワーク読取 (偽の応答でだけ試験)。
- 実際の端末 (TTY) での `questions` の操作 (テストはパイプ入力)。
- 既存ルール優先の判定・変更案の意味の適切さ (AI の読取による)。CLIの反映と復元は機械試験あり。
- モデル・effortを指定した実際のAI起動、クライアントの利用可能モデル。
- 全体コピーのOSメタデータの完全再現、外部サービスの接続。
